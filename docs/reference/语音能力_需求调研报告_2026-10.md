## 0. 摘要

本次调研要回答的不是「选哪家 API」，而是「我们要做一个什么东西、它必须满足什么、怎么证明它做到了」。

三条结论先摆在这里：

1. **产品边界应按「语音能力层」定义，而不是按某个具体功能定义。** 一期交付的是三件事：实时语音对话（ASR + 编排 + TTS）、录音批量转写、音色管理。业务侧通过统一 API 调用，不直接依赖任何供应商。
2. **延迟与准确率必须写成可验收的数字，否则项目无法收敛。** 建议基线：端到端 p50 ≤ 1.0s、p95 ≤ 1.8s；主流语种 WER ≤ 8%、关键实体准确率 ≥ 95%；TTS 首字节 ≤ 200ms。
3. **合规是一期需求，不是上线前补的作业。** EU AI Act 第 50 条透明度义务已于 2026 年 8 月 2 日生效：与 AI 交互需告知、合成音频需可标识。这两个能力必须进 MVP，不能放二期。

成本量级：按 3 分钟会话计，自建链路单会话约 **$0.05**（中低价位音色，约 $0.018/分钟）；直接买托管语音 Agent 平台约 **$0.09–0.14/分钟**（即 $0.27–0.42/会话）。量小时买更划算，量大时自建更划算，拐点大致在月 15–27 万分钟（5–9 万会话）。

## 1. 背景与目标

### 1.1 业务背景

产品需要「能听会说」的能力：用户用语音输入，系统用语音回复；同时要把历史录音转成可检索的文本。当前若按功能逐个接供应商，会出现三个问题：同一家供应商被多处硬编码、延迟不可控、成本无法按场景归因。

因此需要建设一层语音能力中台，对上提供稳定接口，对下屏蔽供应商差异。

### 1.2 项目目标（可度量）

| 目标 | 度量方式 | 目标值 |
|---|---|---|
| 用户体验可用 | 端到端语音往返延迟 | p50 ≤ 1.0s，p95 ≤ 1.8s |
| 识别可信任 | 金标集 WER/CER | 主流语种 ≤ 8%，关键实体 ≥ 95% |
| 合成自然 | 盲测偏好 + 首字节延迟 | CMOS ≥ -0.3；TTFB ≤ 200ms |
| 成本可预测 | 单会话成本 / 单分钟成本 | 有明确模型与月度对账 |
| 可扩展 | 新增语种/供应商的接入工时 | ≤ 5 人日 |
| 合规可过审 | 法务 checklist | 全部通过，无高危项 |

### 1.3 成功标准（项目级）

- MVP 上线后，业务方接入新场景**不需要改业务代码**，只改配置；
- 任一供应商故障时，**自动降级**，用户侧无感知（错误率上升 < 1%）；
- 月度账单可按「场景 / 语种 / 供应商」三维拆分，误差 < 5%。

## 2. 调研方法与信息来源

| 方法 | 覆盖内容 | 局限 |
|---|---|---|
| 厂商官方文档与定价页 | 能力边界、语种、计价单位、SLA | 定价单向乐观，需商务复核 |
| 第三方榜单（Speech Arena、Artificial Analysis、Open ASR Leaderboard） | 相对水平、趋势 | 榜单语料与真实业务分布不同，只能当先验 |
| 公开基准（FLEURS、LibriSpeech） | 跨语种 WER 参考 | 朗读语料，不等于真实噪声场景 |
| 工程社区与事故复盘（LiveKit / Pipecat 文档、开发者讨论） | 打断、回声、端点检测的坑 | 个案，需自行验证 |
| 法规文本与律所解读（EU AI Act 第 50 条及配套指南） | 合规义务 | 解释仍在演进，需法务确认 |

> 本次调研**未包含用户访谈与真实业务音频抽样**，这是最大的信息缺口。第 15 节把它列为需求冻结前的必做项。

## 3. 场景与角色

### 3.1 角色

| 角色 | 关注点 | 对需求的影响 |
|---|---|---|
| 终端用户 | 响应快、听得懂、能打断 | 延迟、打断、口音鲁棒性 |
| 业务产品经理 | 配置话术、看数据 | 管理后台、埋点、A/B |
| 研发工程师 | 接口稳定、易调试 | API 契约、SDK、沙箱环境 |
| 运维/SRE | 可观测、可降级 | 监控指标、熔断、告警 |
| 法务/合规 | 授权、披露、数据留存 | 音色授权、AI 标识、审计日志 |
| 财务 | 成本可归因 | 计量、配额、账单拆分 |

### 3.2 场景清单（按优先级）

| ID | 场景 | 形态 | 关键约束 | 优先级 |
|---|---|---|---|---|
| S1 | 实时语音问答 | 双向流式，可打断 | p95 < 1.8s，支持 barge-in | P0 |
| S2 | 任务型语音办理 | 多轮，需调工具/查库 | 话术可控、可审计、可转人工 | P0 |
| S3 | 录音批量转写 | 文件上传，异步 | 说话人分离、时间戳、导出 | P0 |
| S4 | 内容配音 | 文本转音频，非实时 | 音色一致、长文本稳定、批量 | P1 |
| S5 | 实时字幕 | 单向流式输出 | 低延迟、断句可读 | P1 |
| S6 | 多语种客服（10+ 语种） | 跨语种路由 | 语种自动识别、按语种选引擎 | P1 |
| S7 | 电话接入（PSTN） | 8kHz 窄带 | 回声消除、窄带鲁棒性 | P2（视业务） |

### 3.3 核心用户旅程（S1）

```
用户授权麦克风 → 建立 WS → 用户说话
  → [VAD] 检测到语音起始
  → [ASR] 流式 partial（<300ms 首字）
  → [端点检测] 判定说完（语义 + 静音）
  → [NLU/LLM] 流式生成回复（首 token <500ms）
  → [TTS] 按句流式合成（首字节 <200ms）
  → 播放中若用户开口 → [打断] 停止播放、清空缓冲、回到监听
  → 会话结束 → 落库（转写、音频、耗时、成本）
```

## 5. 需求总览

需求分为 7 个模块，编号规则 `FR-<模块>-<序号>`：

| 模块 | 代号 | 说明 | 一期是否交付 |
|---|---|---|---|
| 语音识别 | ASR | 流式与批量转写 | 是 |
| 语音合成 | TTS | 流式合成、音色、克隆 | 是 |
| 会话编排 | DIA | 轮次、打断、工具调用 | 是 |
| 转写服务 | TRS | 文件任务、分离、导出 | 是 |
| 音色资产 | VOX | 音色库、克隆、授权台账 | 是（克隆仅限内部授权音色） |
| 平台管理 | PLT | 配额、计量、审计、灰度 | 是 |
| 开放集成 | API | 统一接口、SDK、沙箱 | 是 |

优先级采用 MoSCoW：**M**=必须有（MVP）、**S**=应该有（GA 前）、**C**=可以有（后续）、**W**=本期不做。

## 6. 功能性需求

### 6.1 语音识别（ASR）

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-ASR-01 | 流式识别：WebSocket 推流，20ms 帧，返回 partial 与 final | M | 首 partial p95 ≤ 300ms；final 在端点判定后 ≤ 300ms |
| FR-ASR-02 | 端点检测：静音阈值 + 语义判定可组合 | M | 可配置 300–1,200ms；金标集上「说完了」误判率 ≤ 8% |
| FR-ASR-03 | 多语种识别 + 自动语种判定 | M | 覆盖约 12 个语种；≥3s 语音的语种判定准确率 ≥ 95% |
| FR-ASR-04 | 中英混说（code-switching） | M | 单句混说时，专有名词与数字不丢失；人工抽检错误率 ≤ 10% |
| FR-ASR-05 | 热词 / 上下文偏置 | M | 支持单次请求注入 ≤500 词表；专名召回相对提升 ≥ 20% |
| FR-ASR-06 | 逆文本规整（ITN）与标点 | M | 金额、日期、电话、邮箱、型号格式正确率 ≥ 98% |
| FR-ASR-07 | 词级时间戳 | S | 偏差 ≤ 100ms；用于字幕对齐 |
| FR-ASR-08 | 说话人分离（diarization） | S（转写场景 M） | 双人对话 DER ≤ 15% |
| FR-ASR-09 | 噪声与远场鲁棒性 | M | 10dB SNR 下 WER 相对增幅 ≤ 5 个百分点 |
| FR-ASR-10 | 口音 / 方言适配 | C | 按目标市场补充，先做评估不承诺指标 |
| FR-ASR-11 | 敏感内容与时政词处理 | M | 按业务策略返回掩码或拒绝；不返回不雅内容 |
| FR-ASR-12 | 多供应商路由与降级 | M | 主供应商错误率超阈值 60s 内自动切换，业务无感 |

### 6.2 语音合成（TTS）

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-TTS-01 | 流式合成：边生成边下发 | M | 首字节 p95 ≤ 200ms（Cartesia 类）；单 chunk ≤ 200ms 音频 |
| FR-TTS-02 | 多语种音色库 | M | 12 语种 × ≥2 音色；跨语种同一 persona 主观一致性 ≥ 4/5 |
| FR-TTS-03 | 文本规范化 | M | 数字、缩写、URL、多音字正确率 ≥ 98% |
| FR-TTS-04 | 韵律控制（语速/停顿/重音） | S | 支持 SSML 子集；语速 0.5–2.0x 不失真 |
| FR-TTS-05 | 情感与风格标签 | S | 至少 4 种风格，盲测可区分 ≥ 80% |
| FR-TTS-06 | 长文本稳定合成 | M | 单次 ≤5,000 字符；分段合成无断音、无重复、无截断 |
| FR-TTS-07 | 音色克隆（仅限已授权音色） | S | 30s–3min 样本；相似度主观 ≥ 4/5；必须先有授权台账记录 |
| FR-TTS-08 | 话术缓存 | M | 固定话术命中率 ≥ 60%，命中不产生合成费用 |
| FR-TTS-09 | 输出格式与采样率 | M | PCM / Opus / MP3；24kHz 与 8kHz 窄带 |
| FR-TTS-10 | 合成失败降级 | M | 失败时回落备用供应商；仍失败播预录提示音，不静默 |

### 6.3 会话编排（DIA）

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-DIA-01 | 轮次管理（turn taking） | M | 支持「用户说完→系统说」与「系统说完→等待」两种模式 |
| FR-DIA-02 | 打断（barge-in） | M | 用户开口后 ≤ 300ms 停止播放并清空缓冲；误打断率 ≤ 5% |
| FR-DIA-03 | 回声消除 / 自听过滤 | M | 外放场景下，系统不把自己的声音识别为用户输入（误触发 ≤ 1 次/10 分钟） |
| FR-DIA-04 | 静默与超时策略 | M | 可配置 3 档（追问 / 重述 / 挂断），行为可测 |
| FR-DIA-05 | 工具调用与业务查询 | M | 单轮 ≤ 2 次工具调用；失败有兜底话术；全链路可追溯 |
| FR-DIA-06 | 转人工 | S | 触发条件可配置；转接时传递完整上下文与转写 |

| FR-DIA-08 | 实时语音模型路由 | C | 闲聊场景可切端到端模型，业务场景走级联 |

**接口草案**（供研发评审，不是最终契约）

```
WS  /v1/asr/stream?language=auto&diarize=false&hotwords_id=xxx
    ← 16kHz/24kHz PCM 帧
    → {type:"partial"|"final"|"error", text, start_ms, end_ms, confidence}

WS  /v1/tts/stream
    → {text, voice_id, language, format:"pcm_24k", speed:1.0}
    ← 音频帧 + {type:"done", first_byte_ms, audio_ms}

POST /v1/transcriptions           # 创建批量任务
GET  /v1/transcriptions/{id}      # 查询
POST /v1/voices/clone             # 需先提交授权凭证
GET  /v1/usage?group_by=scene,language,provider
```

## 7. 非功能性需求

| ID | 类别 | 要求 | 验收方式 |
|---|---|---|---|
| NFR-PERF-01 | 延迟 | 端到端 p50 ≤ 1.0s、p95 ≤ 1.8s；ASR 首字 p95 ≤ 300ms；TTS 首字节 p95 ≤ 200ms | 生产环境埋点，连续 7 天统计 |
| NFR-PERF-02 | 并发 | 单区域 100 路并发语音会话（架构可扩至 200），P99 延迟不劣化超过 20% | 压测报告 |
| NFR-SCALE-01 | 扩展性 | 新增语种/供应商不改业务代码；横向扩容线性度 ≥ 0.8 | 架构评审 + 演练 |
| NFR-AVAIL-01 | 可用性 | 月度 99.9%；单供应商故障时整体 ≥ 99.95% | 监控与故障演练 |
| NFR-REL-01 | 故障切换 | 主供应商不可用时 ≤ 2s 切备；切换对用户表现为轻微延迟增加 | 混沌演练（每月一次） |
| NFR-ACC-01 | 准确率 | 主流语种 WER ≤ 8%；关键实体准确率 ≥ 95% | 金标集回归 |
| NFR-SEC-01 | 安全 | TLS 1.3 传输、静态加密、密钥 90 天轮换；音频 URL 短期签名 | 安全评审 |
| NFR-PRIV-01 | 隐私 | 音频默认留存 7 天、文本 90 天，可按租户配置；删除请求 ≤ 30 天完成 | 抽查 + 审计 |
| NFR-COMP-01 | AI 披露 | 会话开始 10s 内明确告知「正在与 AI 交互」；合成音频携带 AI 标识 | 法务 checklist 逐项签核 |
| NFR-COMP-02 | 克隆授权 | 无授权凭证不得创建克隆音色；授权到期自动停用 | 系统强制校验，不可绕过 |
| NFR-COST-01 | 成本 | 单会话成本 ≤ $0.10（不含电话费）；月度波动告警阈值 ±20% | 账单对账 |
| NFR-OBS-01 | 可观测 | 每次调用带 request_id，串起 ASR/LLM/TTS 三段耗时 | 链路追踪抽样 |
| NFR-I18N-01 | 国际化 | 语种、数字、日期、货币格式按 locale 输出 | 多语种用例 |
| NFR-MAINT-01 | 可维护性 | 接入一家新供应商 ≤ 5 人日；模型升级有回滚路径 | 实操验证 |

## 8. 约束与不做的事

**约束**

1. 部署在海外云（EU / US region），一期不私有化；架构保留可私有化替换点。
2. 语音数据涉及个人信息，默认最小化留存，跨境需评估。
3. 供应商定价与模型版本波动大，计费与路由必须可配置，不能硬编码。
4. 团队规模与工期决定一期只能做「能力层」，不做完整业务话术平台。

**明确不做（Out of Scope，v1）**

| 不做 | 原因 |
|---|---|
| 声纹识别 / 声纹身份认证 | 属生物识别，合规成本与风险远高于收益 |
| 端侧离线识别与合成 | 与「海外云优先」的前提冲突，且维护成本高 |
| 自研语音模型 | 投入产出不成立，除非后期量级足够大 |
| 实时语音翻译 | 依赖翻译质量与延迟叠加，单独立项 |
| 情绪识别 / 心理状态推断 | 高敏感，易触发监管与伦理问题 |
| 音乐 / 音效生成 | 与业务无关 |
| 全自动外呼 | 涉及骚扰与合规风险，需单独评估 |

## 9. 容量模型与单位经济性

### 9.1 单会话成本（3 分钟，用户说话占 50%）

| 成本项 | 计算 | 低成本组合（Cartesia 类） | 高质量组合（ElevenLabs 类） |
|---|---|---|---|
| ASR | 1.5 分钟 × $0.0077 | $0.012 | $0.012 |
| LLM | 约 1,200 输入 + 400 输出 token | $0.003 | $0.003 |
| TTS | 1,200 字符 × $30 / $220 每百万 | $0.036 | $0.264 |
| 基础设施 | 存储、日志、观测均摊 | $0.002 | $0.002 |
| **合计** | | **≈ $0.053** | **≈ $0.281** |
| **折合每分钟** | | **≈ $0.018** | **≈ $0.094** |
| 叠加 PSTN | + $0.007/分钟 | + $0.021 | + $0.021 |

对照：直接采购托管语音 Agent 平台，全包价约 **$0.09–0.14/分钟**（即 $0.27–0.42/会话）。也就是说，**自建只在 TTS 走中低价位时才有成本优势**；如果坚持用最贵的表现力音色，自建并不比买便宜多少，只是换来了可控性。

### 9.2 并发与月度规模

单向并发 C、平均利用率 u（语音业务通常 5%–15%，峰谷差极大）：

```
月会话数 ≈ C × (60 / 3) × 24 × 30 × u = C × 14,400 × u
```

| 并发 C | u=10% 月会话 | 对应月分钟 | 低成本组合月成本 | 高质量组合月成本 |
|---|---|---|---|---|
| 20 | 28,800 | 86,400 | ≈ $1,530 | ≈ $8,100 |
| 50 | 72,000 | 216,000 | ≈ $3,820 | ≈ $20,200 |
| 100 | 144,000 | 432,000 | ≈ $7,640 | ≈ $40,500 |
| 200 | 288,000 | 864,000 | ≈ $15,300 | ≈ $81,000 |

注意：**成本由峰值并发和话术长度驱动，不由注册用户数驱动**。做预算时先问「同时多少路」，再问「每通多久」。

### 9.3 自建的临界点

按 50 路并发、6 卡 L4 集群（含冗余）计，月固定成本约 **$2,600–5,000**（含运维）。代入 9.1 的低成本组合，云 API 边际成本约 $0.053/会话：

- 自建固定成本 ÷ 云成本 = 约 **5 万–9 万会话/月**（15 万–27 万分钟）时打平。
- 若 TTS 走 ElevenLabs 价位，自建打平点会前移到约 1 万–2 万会话/月——但前提是自建方案的音质能被接受，而这一点恰恰最难达到。

**建议**：一期全部走云 API；把「离线批量转写」作为自建的第一块试验田（对延迟不敏感、GPU 利用率可打满）。

## 11. 技术可行性结论（与选型报告的对应关系）

| 需求模块 | 技术路线 | 一期候选 | 可行性 | 主要风险 |
|---|---|---|---|---|
| ASR 流式 | 云 API WebSocket | Deepgram Nova-3、AssemblyAI U-3.6 Pro、Scribe v2 Realtime | 高 | 端点检测在真实对话中的误判 |
| ASR 批量 | 云 API 异步 / 自建 | Scribe v2、Chirp 3、Whisper-turbo | 高 | 长音频超时与计费 |
| ASR 新候选 | 云 API | Microsoft MAI-Transcribe-1.5（宣称平均 WER 约 3.9%）、Mistral Voxtral 3（50+ 语种，配 LiveKit SDK） | 待验证 | 宣称值与真实场景差异，需自测 |
| TTS 流式 | 云 API 流式 | Cartesia Sonic 3.6、ElevenLabs Flash | 高 | 首字节在弱网下的抖动 |
| TTS 表现力 | 云 API | ElevenLabs Eleven v4 | 高 | 成本 |
| TTS 自建 | 开放权重 | Breeze TTS 2、CosyVoice | 中 | **Breeze 权重仅限研究用途**，商用需授权 |
| 会话编排 | 开源框架 | LiveKit Agents 1.5（自适应打断）、Pipecat（turn management） | 高 | 打断与回声的调参成本 |
| 代理层 | 自研 | 统一网关 + 路由 + 计量 | 高 | 供应商差异抽象不彻底 |

**两条工程结论**

1. **编排层不要自研从零开始。** LiveKit Agents 或 Pipecat 已经把 VAD、打断、轮次、回声处理这些脏活做完了，2026 年的版本还引入了「自适应打断」（区分真打断与「嗯、对」这类反馈音），这是自研最容易翻车的地方。自研的应该只有「供应商路由 + 计量 + 业务工具调用」。
2. **评测必须自动化。** 每次换模型、换供应商、调参数，都要跑同一套金标集。没有这条，所有的「感觉变好了」都不可信。

### 13.1 金标集规范

| 项 | 要求 |
|---|---|
| 规模 | 300–500 条音频，覆盖 12 语种，每语种 ≥20 条 |

### 13.2 上线门槛（Ship Gate）

| 检查项 | 通过条件 |
|---|---|
| 准确率 | 主流语种 WER ≤ 8%；实体准确率 ≥ 95% |
| 延迟 | 生产埋点连续 7 天：p50 ≤ 1.0s，p95 ≤ 1.8s |
| TTS 质量 | 盲测 CMOS ≥ -0.3；无「机器味」集中差评 |
| 稳定性 | 72 小时压测错误率 < 0.5%；故障切换演练通过 |
| 合规 | 法务 checklist 全部签核；披露与标识可现场演示 |
| 成本 | 单会话成本 ≤ $0.10；看板与账单误差 < 5% |
| 可运维 | 四类告警可触发；回滚演练 < 10 分钟 |

任何一项不通过，不得进入 GA。

## 16. 附录

### 16.1 关键公式

```
WER = (S + D + I) / N          # 替换、删除、插入 / 参考词数
CER = 同上，按字符计            # 中文等无空格语言用 CER

端到端延迟 = 上行 + VAD/端点 + ASR终版 + LLM首token + TTS首字节 + 下行缓冲
（注：流式链路中 ASR partial 可与 LLM 并行，实际感知延迟低于串行相加）

单会话成本 = ASR分钟×单价 + LLM token×单价 + TTS字符×单价 + 基础设施均摊
月会话数 ≈ 并发 × (60/平均时长) × 24 × 30 × 平均利用率
```

### 16.2 术语

| 术语 | 含义 |
|---|---|
| VAD | 语音活动检测，判断有没有人说话 |
| 端点检测 / turn detection | 判断「这句话说完了没有」，决定何时触发回复 |
| barge-in | 用户打断系统播报 |
| TTFB | 首字节延迟，TTS 从请求到第一帧音频 |
| RTF | 实时率，生成耗时 ÷ 音频时长，越小越好 |
| WER / CER | 词错率 / 字错率 |
| CMOS | 成对比较主观评分，衡量音质相对差距 |
| DER | 说话人分离错误率 |
| ITN | 逆文本规整，把「一千二百块」转成「1200 元」 |
| PSTN | 公共电话网，8kHz 窄带，回声问题突出 |
